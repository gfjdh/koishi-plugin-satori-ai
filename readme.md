# koishi-plugin-satori-ai

[![npm](https://img.shields.io/npm/v/koishi-plugin-satori-ai?style=flat-square)](https://www.npmjs.com/package/koishi-plugin-satori-ai) [![MIT License](https://img.shields.io/badge/license-MIT-blue.svg?style=flat)](http://choosealicense.com/licenses/mit/) ![Language](https://img.shields.io/badge/language-TypeScript-brightgreen) ![Static Badge](https://img.shields.io/badge/QQ交流群-2167028216-green)

当前版本: 2.5.0  •  最后更新: 2026-11-19

基于 Koishi 框架的智能聊天机器人插件（Satori 适配器），集成多轮对话、分层长期记忆与用户画像、群聊记忆与省流、群日报/周报/月报/年报、日程感知、主动消息、好感度/情绪系统，可选 Puppeteer、天气感知、广播与小游戏等扩展功能，支持深度自定义。

[作者主页](https://gfjdh.cn)

适配目标：Satori 适配器（对其他适配器兼容性未经过完整测试）。

使用前可在诸如 DeepSeek、火山引擎等平台获取 API key：

- DeepSeek 示例 baseURL: `https://api.deepseek.com`
- 火山引擎 示例 baseURL: `https://ark.cn-beijing.volces.com/api/v3`

注意：不同提供商的温度范围可能不同（例如 DeepSeek 0-2，火山引擎通常 0-1）。

对于部署者行为及其产生的任何纠纷，Koishi 及本插件概不负责。

如果想修改插件内置的本地化文本，可编辑本项目的 `locales/zh` 内容。

## 最近更新要点

### v2.5.0：往期报刊

- **自动存档**：每次报告发送成功后，报纸图片写入 `${dataDir}/reports/g_<群号>/<YYYYMMDD>.png`，数据库 `sat_report` 保存相对路径和完整结构化内容（分节、统计、榜单、最喜欢）；同一群同一天重复生成会覆盖，永久保留。
- **查看往期**：群内发送 `往期报刊 20260101`（别名 `往期报纸`，权限 0），只发当期报纸图片；图片丢失时用数据库里的结构化内容重新渲染，没有 Puppeteer 时退回纯文本。
- **不重发最喜欢**：查看往期只发报纸本身，不重发当时的好感度消息。

### v2.4.0：群日报改版为《心眼报》

- **报纸版式**：日报/周报/月报/年报渲染成一张整版报纸，版面直接占满图片、不留背景。从上到下是报头（刊名、日期、期号）、栏名、顶栏（本期热词 + 时间范围）、24h 活跃轨迹、头条、导语、本群要闻、群友金句、活跃榜、点评与报尾。报头衬线字；要闻和金句用小卡片网格，要闻一行两个、奇数时最后一条横跨两栏，金句一行两个，首条要闻首段保留首字下沉。
- **刊名可配**：`report_masthead`（默认「心眼报」）决定报头刊名；报尾署名与点评落款读取 `nick_name_list` 的第一个昵称，不再硬编码角色名。
- **24h 活跃轨迹**：顶栏下方一张 24 根柱子的迷你柱状图，统计最近 24 小时每小时的消息数，并标出峰值时段。
- **栏目**：模型按 `【头条】【导语】【要闻】【金句】【活跃】【点评】【热词】` 分栏输出，渲染器逐栏排版。
  - 要闻可以有多条，每条写成 `小标题｜正文`，条数由模型按材料决定；每条不跨栏。
  - 金句从单独的「金句候选」列表里选：候选由本地从区间内全部群友消息中抽取、去重，复读过的句子标注「复读 N 次」，发言人取第一个说这句话的人；模型只能从候选里选，不能改写，也不能选自己。
  - 活跃榜的发言条数由本地统计（准确），模型只写人物点评；年报的原始消息只保留 30 天，所以榜单标题改成「近期活跃榜」。
  - 热词 3–5 个，放在顶栏。
- **点评排版**：标题「点评」，正文右缩进，落款 `—— 昵称` 右对齐。
- **期号**：每成功发一份报告，`sat_meta.reportCount` 加一，报头显示「第 N 期」。
- **最喜欢三档**：模型在 `【今日/本期最喜欢】昵称｜档位｜理由` 里同时给出人选、档位和理由，档位为「有点喜欢 +10」「喜欢 +20」「非常喜欢 +30」，默认中间档，避免每期都给最高档。选人只看发言质量和角色自己的喜好，不看发言频率。
- **分两条消息发送**：先发报纸图片，再发最喜欢（带 @ 和理由）：`今日最喜欢：@某某，因为……（非常喜欢 +30好感）`。图片不和其他文字混在同一个数组里——Koishi 的 `h.normalize` 不会把数组里的字符串解析成元素，混排会让图片退化成一段 base64 文本。
- **回退**：模型没按栏目输出时，整段原文作为「本群要闻」单栏渲染；完全没有标记时退回旧的纯文本卡片，不会因为格式漂移导致整张图发不出去。
- **一条指令，按日期自动升级**：群内发送 `群日报`（别名 `日报`），按执行时的**本地日期（零点切分）**自动选择报告类型，优先级 **年 > 月 > 周 > 日**。
  - 1 月 1 日 → **年报**，召回上一个自然年，最高月粒度（月 → 周 → 日 → 话题 → 未归档原文）。
  - 每月 1 日 → **月报**，召回上一个自然月，最高周粒度（周 → 日 → 话题 → 原文）。
  - 周一 → **周报**，召回上周一 00:00 至本周一 00:00，最高日粒度（日 → 话题 → 原文）。
  - 其余日期 → **日报**，召回前一天 00:00 到当天 00:00 的群聊，最高话题粒度（话题 → 原文）。
- **篇幅**：日报约 1200–1500 字，周报约 2000–2500 字，月报约 3000–3600 字，年报约 4000–4800 字（含各栏目）。
- **选材**：按对应最高粒度由粗到细取，粗层级覆盖过的时段不会再用细层级重复补；未归档原文按报告类型截断，避免输入失控。
- **时间范围与卡片**：日报固定取前一天 00:00 ~ 当天 00:00，周/月/年报取对应自然周期，不看上次报告时间；同一天重复执行会重新生成同一段内容。有 Puppeteer 时渲染成报纸图片，没有时退回纯文本。
- **群级任务**：日报/周报/月报/年报不注入提问者的个人画像、好感度、昵称、心情等，材料也不标「提问者」，只保留人格、群画像与群常识。
- **输出上限**：单次请求单独放宽输出 token 并关闭思考模式，避免长报告被截断或生成过慢；正文保留段落格式，不受普通回复的括号过滤影响。

### v2.3：群聊记忆、省流、日程与主动消息

- **群聊记忆（默认关闭）**：`enable_group_memory` 开启后，机器人为每个它回过话的群建立独立记忆，与按人记忆并存。群 scope 使用 `g:<群号>` 前缀，不会和用户 id 冲突。
  - 群消息不逐条判断话题（成本会失控），而是按结构切块：同一自然日内、间隔不超过 20 分钟的一段连续发言为一块；单块最多 300 条、最长 4 小时；不足 100 条的块直接跳过、不调用模型。切块本身零模型调用，每块只归档一次。
  - 归档前做抽取式压缩：丢弃少于 4 字（“草”“哈哈哈”）和超过 200 字（公告/复制粘贴）的发言，同一个人连续发言合并成一行。原始群消息保留 30 天，之后由心跳统一清理。
  - 群记忆有自己的六级金字塔和**群画像**（群特征、活跃群友、群友关系、长期话题与梗、群规与长期要求、其他）。群画像只在出现新的归档块时更新，不会反复空转。
  - 注入时群金字塔与个人金字塔并列，但群记忆只注入最近一条年总结；私聊不注入群记忆。`sat.memory.view group` 查看当前群，`sat.memory.view <群号>` 查看指定群。
  - 只有机器人真的回过话的群才会被记录；重启时从最近 `memory_active_window_days`（默认 7 天）内活跃过的群恢复，没人理 bot 的群不会占存储和心跳名额。
- **群聊「省流」**：群内发送 `省流`，把“你上次在本群发言到现在”的群聊用角色口吻讲成一段概要；篇幅按材料长度等比换算（材料 7 字≈概要 1 字，一天的量约 500 字，下限 150、上限 3000）。
  - `-d N` / `-m N` / `-y N` 指定最近 N 天/月/年，可叠加；不填时从你上次在本群发言算起，从没说过话则按最近 24 小时。
  - 选材按“年 → 季 → 月 → 周 → 日 → 话题 → 未归档原文”由粗到细取，同一时段不会同时出现粗、细两份；未归档原文全文召回，不截断。
  - 只沿用正常对话的系统提示（人格、画像、好感度、心情、常识等），不注入金字塔和关键词召回，也不写记忆、不扣使用次数。你的发言会标为「提问者」，机器人自己的发言标为「你」。
  - 有 Puppeteer 时渲染成图片卡片，没有时退回纯文本。开启好感度时，好感度低于 `favorability_div_2`（默认 150）不能使用。
- **觉的日程**：`enable_schedule` 开启后，插件从 `${dataDir}/schedule.json` 读取日程，按当前时刻挑一条注入系统提示，告诉模型“没有互动时你会去做什么”。
  - 文件不存在时自动生成一份只演示写法的示例；按文件修改时间热加载，改完不用重启。
  - 支持 `start/end`（`HH:MM`，省略 end 表示到当天结束，end 小于 start 表示跨午夜）、`days` 限定星期、`activities` 候选活动、`variations` 小插曲、`vars` 变量池（条目可带 `note` 简介）。
  - `dayView: true` 时注入全天视图（已经做过 / 现在 / 接下来）；同一时段内所有用户拿到的文字逐字节相同（按“日期 + 条目”确定性选择），不会破坏前缀缓存。
  - 只在每段对话开头几轮注入（短期记忆条数少于 `schedule_inject_below_entries`，默认 10 条）；心情为烦躁/生气时跳过。当前时刻没有任何条目命中时不注入。
- **短期记忆 TTL**：`short_term_ttl_minutes` 默认 60，用户沉默超过该时长后，用户↔bot 的短期对话记忆自动清空；`0` 关闭。每 `short_term_sweep_minutes`（默认 5）分钟扫描一次，读取时也会懒清理。群聊环境（所有人发言）不受 TTL 影响，仍按条数截断。
- **私聊主动消息**：`enable_proactive` 开启后，用户沉默一段随机时间（`proactive_min_idle_minutes` ~ `proactive_max_idle_minutes`，默认 60~120 分钟）后，机器人会基于记忆主动开口一次。
  - 安静时段（默认 23:00–08:00）不发送；沉默超过 `proactive_max_idle_hours`（默认 24 小时）不再主动；可设 `proactive_min_favorability` 好感度门槛（默认 1000，`0` 表示不设门槛）。
  - 一次沉默周期只主动一次，用户不回复就不再追发，直到他再次发言重新计时；全局每分钟最多一条。
  - 主动消息只写短期记忆，不写长期记忆、不扣使用次数；状态保存在内存里，插件重载后清空（重启不会突然给所有历史用户群发）。
- **归档输入使用固定发言人标签**：归档提示里每行只用「用户」和昵称列表第一个（机器人名字）标记发言人，昵称不再参与身份判断；用户发言里的昵称（昵称列表与「情侣合照」中的专属昵称）会被抹掉，避免总结器把“名字：台词”当成换人。归档与画像提示词都要求用这个名字指代机器人，不再写成「助手」「AI」「机器人」等泛称。群聊用「用户（昵称）」，省流时机器人自己的发言显示为「你」、提问者额外标注。
- **记忆注入排序与预算**：分层记忆改为“由粗到细、段内时间正序”，年/季/月等稳定内容占住缓存前缀，新话题/日总结追加在末尾；取消 `memory_context_max_chars` 预算，完整注入，不再按长度截断或丢弃层级。
- **API 请求健壮性**：思考模型返回空正文时自动关闭思考重试一次；429/503 按指数退避并带抖动、优先遵守 `Retry-After`；所有重试之间仍有 `retry_delay_time` 间隔；没有配置任何可用 key 时直接返回明确错误，而不是静默失败。
- **思考强度与八股词汇**：新增 `reasoning_effort`（low/medium/high/max，默认 low）；新增 `remove_words`，用 `-` 分隔的词汇会从回复中直接删除（只删词、不删整句，优先级最高）。
- **每日次数与心情修复**：每日使用次数改用完整日期键，修复跨月同一天不重置的问题；次数与日期同一次写入，避免中断后重复重置。心情跨天重置为 `mood_div_1 + value_of_output_mood`，并先重置再叠加本次变化；「点心盒」在下一次对话时自动消耗并清零。
- **一碰一 AI 评估**：改用训练好的线性评估权重（`src/oneTouchWeights.ts`），在 2–10 级的成对自对弈中相对旧评估约 54.5% 胜率（平局按 0.5 计）。权重文件缺失或维度不符时自动回退旧评估。
- **其它**：随机插话会先把触发它的那条消息写进群聊环境，机器人自己的回复也会留痕；私聊游戏进行中，游戏输入不再同时触发 AI；群画像的“活跃群友”条目在展示和注入时会补上昵称主语。

### v2.2：全时间范围记忆注入

- **不再每级只取一条**：此前系统提示实际只注入「最近一年 + 最近一季 + 最近一月 + 最近一周 + 最近一天 + 最近一个话题」，更早的记忆即使存在也不会出现。现在每一级都会注入其父周期内的**全部**节点：所有历年总结 → 今年各季总结 → 本季各月总结 → 本月各周总结 → 本周每日总结 → 尚未归档成日的所有话题。父周期尚未闭合时，下一级正好补上这段空档，时间轴上不会留下缺口。
- **每条记忆带时间范围**：话题精确到分钟，日/周/月/季/年精确到日期，段落按由粗到细排列（历年 → 话题）、段内按时间正序排列，模型能直接看出每段记忆覆盖的时间。粗粒度在前也让最稳定的内容占住最长的缓存前缀，新追加的话题/日总结不会顶掉前面的缓存。
- **召回不重复**：关键词召回会排除金字塔里已经注入的全部记忆，避免同一段内容以两种形式重复出现。
- **预算默认提高到 8000 字**（v2.3 起该预算与 `memory_context_max_chars` 已取消，分层记忆改为完整注入）：`memory_context_max_chars` 的默认值由 2000 提到 8000（重度用户完整覆盖实测约 2000–6200 字）。超出预算时先放弃召回，再让每一级只保留最新一条，然后从最粗的层级整段丢弃，最后才硬截断（保留开头）；前两步始终优先保留最近的内容。
- `sat.memory.view` 与注入内容一致：命令返回与系统提示注入**完全相同**的分层记忆文本（格式、顺序一致），可传 `[target]` 指定查看对象，省略时查看当前会话的作用域。原来的作用域/对话数/最近对话/画像摘要输出已移除。

### v2.1：历史积压归档提速与画像质量

- **稀疏日合并归档**：连续多个对话稀疏的自然日（单日 ≤ 30 条）会合并成**一次**模型调用，按日期分别返回每一天的话题与总结，日界仍然严格保留。一次最多合并 5 个有对话的日子（可跨过空白日期，向前最多扫描 20 天），总量不超过 80 条对话。历史回填的调用量因此降到大约 1/5，实测归档速度从约 15 个 scope-day/分钟提升到 45 个/分钟以上。
  - 合并产生的多条记忆与归档游标在**同一个事务**里提交；任何一天缺失或解析失败都会整批作废并退回单日归档，不会把某天的内容写进别的日期。
- **异常日自动跳过**：某一天被模型内容审核拒绝（`data_inspection_failed` / `inappropriate content`）时立即跳过；其他错误连续失败 3 次后跳过。跳过只推进归档游标，既不会让一个坏日子卡死整个用户的历史补齐，也不会把游标推进到未来。
- **并发心跳**：新增 `summary_concurrency`（默认 10），同时处理多个用户/群；单个用户/群内部仍严格串行以保证归档顺序。配合 `summary_heartbeat_minutes`（默认 10 分钟）、`summary_max_scopes_per_tick`（默认 30）、`summary_max_calls_per_tick`（默认 8）可以显著加快大量历史对话的补齐。
- **近期对话感知**：系统提示中新增「近期对话时间与频率」段——最近一天/一周/一月/一季/一年的轮次、日均轮次与距上次对话的时间，让模型自然表达关心而不是念数字；`dialogue_stats_enabled` 可关闭。该段始终注入，不受记忆长度影响。
- **画像更新窗口**：画像只由最近 `profile_update_window_days`（默认 7 天）内结束的日总结更新，历史回填阶段不再为几个月前的每个日子重复调用模型。
- **积压追平后一次性回填**：某个用户/群的历史全部归档完毕后，用金字塔里的季度/月/周总结补一次画像（每个 scope 只做一次，失败下轮重试），旧历史里的长期信息不会整体丢失。
- **画像召回上限**：注入系统提示的画像条目上限 `profile_context_entries` 默认提高到 100，保留上限 `profile_max_entries` 同步为 100，按重要度/更新时间取前 N 条。

### v2.0：分层长期记忆重构

- **话题 → 日 → 周 → 月 → 季 → 年** 六级金字塔。话题记忆严格不跨自然日；上一级只在一个「已闭合且下层已齐」的周期上生成，每个周期最多一条节点。
- 自然日默认以 **+08 凌晨 04:00** 为界（`memory_timezone_offset` / `memory_day_boundary_hour` 可配）。历史积压按日切块，单日超过 200 条对话时同一天拆成多块，day 级再合并。
- 后台心跳每 10 分钟处理一批活跃用户/群，自动补齐积压；归档与层级汇总共享每次的辅助模型调用预算（`summary_max_calls_per_tick`），预算不够时宁可不建上层，也不会生成缺子项的周/月节点。
- 记忆与归档游标在同一个事务中写入，中断不会丢消息，也不会重复归档。
- 长期记忆从旧版 JSON 文件迁移到 **数据库表**（`sat_dialogue` / `sat_memory` / `sat_knowledge` / `sat_profile` / `sat_meta`）。首次启动会自动迁移一次，之后可用 `sat.memory.migrate` 手动重跑。

### 其它改进

- **检索**：中文无词典分词（unigram + bigram）+ BM25 + 时间衰减，按查询召回相关历史记忆；注入系统提示时按相关度取 TopN，不再按长度截断。
- **用户画像**：由日总结驱动增量更新，不再消耗额外的轮次配额。
- **@ 与昵称前缀**：写入对话记录前会去掉「@bot」和以昵称开场的称呼，避免记忆里堆积「古明地觉 xxxx」这类噪声；其他用户的 @ 仍保留名字。
- Puppeteer 可选集成、天气感知、Broadcast 管理、小游戏与 galgame 模块继续保留。
- 增强频道级并发控制、重复请求检测与请求排队。

详细设计与变更可参见 `docs/memory-refactor-plan.md` 与仓库提交记录。

## 功能特性

- **自然语言交互**
  支持私聊/群聊触发，内置指令、@提及、昵称、随机概率触发与上下文记忆。
- **分层长期记忆**
  短期上下文 + 话题归档 + 日/周/月/季/年汇总 + 关键词召回 + 用户画像 + 常识/群常识知识库。
- **群聊记忆**
  可选的按群记忆：群聊时间块归档、群金字塔与群画像，与按人记忆并存；只有机器人参与过的群才会被记录。
- **群聊省流**
  群内一条指令把“你上次发言以来的群聊”讲成一段概要，篇幅随材料长度等比变化，支持按天/月/年指定范围。
- **群日报 / 周报 / 月报 / 年报**
  同一个 `群日报` 指令按本地日期自动选择：周一生成周报、每月 1 日生成月报、1 月 1 日生成年报，其余日期生成日报；渲染成《心眼报》报纸卡片，含头条、导语、要闻、金句、活跃榜、点评与热词，并附「本期最喜欢」的好感度奖励。
- **日程感知**
  按 `schedule.json` 的时段注入“角色正在做什么”，同一时段文字稳定，改文件即生效。
- **主动消息**
  私聊中用户沉默一段时间后，机器人可基于记忆主动开口一次；支持安静时段与好感度门槛。
- **识图**
  消息里带的图片（以及被引用消息里的图片）可以识别：配置识图模型时先转成文字再注入对话，未配置时直接把图片交给主模型。
- **好感度系统**
  六级情感状态（厌恶/陌生/朋友/暧昧/恋人/夫妻），持有「订婚戒指」可升级为夫妻关系，持有「奶瓶」可建立母子关系（可随时开关解除），影响回复风格与交互限制。
- **情绪系统**
  与好感度并列的心情值，支持可见化反馈、屏蔽词扣减与每日重置。
- **API 集成**
  支持多密钥轮换、自动重试、错误处理，兼容 DeepSeek 格式的 API；可为辅助任务（话题判断、汇总、画像、好感度）单独配置低成本的辅助模型。
- **扩展机制**
  固定对话模板、自定义触发策略、中间件管道；回复内容支持道具后缀（如「猫耳发饰」「觉fumo」）。
- **并发控制**
  频道级并发限制，自动排队处理高负载请求。

额外模块：

- 可选 Puppeteer 集成：用于页面渲染、截图或抓取外部内容（需安装 `koishi-plugin-puppeteer`）。
- WeatherManager：基于配置的天气感知与时效缓存。
- BroadcastManager：广播/消息推送的集中管理与频道屏蔽。
- 小游戏与经济系统：简单的游戏开关、口袋钱（pocket money）与道具消费逻辑。

### 记忆系统

#### 分层结构

```
topic  （一次连续话题，不跨自然日）
  └─ day    （自然日，默认 04:00 分界）
       └─ week    （周一 04:00 起）
            └─ month   （每月 1 日 04:00 起）
                 └─ season  （季度）
                      └─ year    （自然年）
```

- 话题切换由轮数阈值（5–20 条）与辅助模型共同判断；历史积压按自然日逐块归档，话题与日节点都**不跨自然日**。
- 对话稀疏的历史日子会合并归档：连续最多 5 个有对话的日子（单日 ≤ 30 条、合计 ≤ 80 条，可跨过空白日期）走一次模型调用，按日期分别返回各自的总结。合并失败或缺少某一天时整批作废，退回单日归档。
- 只有当一个周期的**所有下层节点**都已产出、且归档游标已经越过该周期末尾时，才会生成周期节点。单子节点、或子节点正文总和不超过 300 字时直接晋升，不额外调用模型；各级汇总的 summary 在提示词里按时间跨度设了字数上限（日 300 / 周 600 / 月 1000 / 季 1500 / 年 2000），只约束输出，不做代码截断。
- 每 10 分钟一次心跳（`summary_heartbeat_minutes`），默认每轮最多处理 30 个活跃用户/群（`summary_max_scopes_per_tick`）、最多 10 个并发（`summary_concurrency`）；每个 scope 的辅助模型调用预算默认 8 次（`summary_max_calls_per_tick`），在归档与层级汇总之间平分。历史积压较多时优先调大并发与单轮 scope 数。
- 某个 scope 的历史没追平前不会生成更高层级；追平后会用高层汇总补一次画像（每个 scope 一次）。
- 原始对话默认永久保留（`memory_retention_days: 0`），汇总后的记忆不会被清理；设为正数则按天数清理。

#### 短期记忆 TTL

- 用户与 bot 的短期对话记忆在空闲 `short_term_ttl_minutes`（默认 60 分钟）后自动清空；设为 `0` 关闭。
- 每 `short_term_sweep_minutes`（默认 5 分钟）扫描一次，读取时也会判断是否过期；主动消息不会刷新空闲计时。
- 群聊环境（`channel_dialogues`，包含所有人发言）不受 TTL 影响，仍按 `channel_dialogues_max_length` 条数截断。

#### 群聊记忆

`enable_group_memory`（默认关闭）开启后，机器人为每个它回过话的群建立独立记忆，与按人记忆并存。群 scope 使用 `g:<群号>`，与用户 id 不会冲突。

- 切块不调用模型：同一自然日内、间隔不超过 20 分钟的一段连续发言为一块；单块最多 300 条、最长 4 小时，不足 100 条的块直接跳过。每块只发起一次归档（被内容审核拒绝时会用脱敏输入重试一次）。
- 归档前做抽取式压缩：丢弃少于 4 字和超过 200 字的发言，同一个人连续发言合并成一行；原始群消息保留 30 天，之后由心跳清理。
- 群记忆同样有话题→日→周→月→季→年六级金字塔，并额外维护一份群画像（群特征、活跃群友、群友关系、长期话题与梗、群规与长期要求、其他）。
- 群画像只在出现新的群归档块后更新；注入时群金字塔只取最近一条年总结，且只在群聊会话中注入，私聊不受影响。
- 只有机器人回过话的群才会被记录；插件启动时从最近活跃的群恢复，没人理 bot 的群不会占存储和心跳名额。
- `sat.memory.view group` 查看当前群，`sat.memory.view <群号>` 查看指定群；群画像用 `sat.get_user_portrait g:<群号>` 查看。

#### 数据存储

| 表 | 内容 |
| --- | --- |
| `sat_dialogue` | 原始对话（`turn` 实时对话、`legacy` 迁移数据、`ambient`/`ambient-bot` 群聊发言与机器人发言） |
| `sat_memory` | 六级记忆节点（`topic/day/week/month/season/year`） |
| `sat_knowledge` | 常识与群常识 |
| `sat_profile` | 增量用户画像与群画像 |
| `sat_meta` | 每个 scope 的归档游标、活跃时间与报告时间 |

旧版 `data/satori_ai/dialogues/<userId>.txt`、`UserPortrait/`、`common_sense.txt` 只在 `sat.memory.migrate` 时读取，**不再写入**；迁移完成后可自行归档备份。

群聊原始消息只保留 30 天（不受 `memory_retention_days` 影响），群记忆节点与群画像长期保留。

#### 检索与注入

- 知识库与历史记忆使用 BM25 + 时间衰减打分，按查询词召回 TopN。
- 系统提示依次注入：近期对话统计（`dialogue_stats_enabled`）、**全时间范围的分层记忆**、群聊记忆金字塔与群画像（群聊中）、按查询召回的历史记忆、用户画像。
- 分层记忆按级注入父周期内的**全部**节点：所有历年总结、今年各季总结、本季各月总结、本月各周总结、本周每日总结，以及最后一个日节点之后尚未归档的话题。每条带 `[起 ~ 止]` 时间范围，段落由粗到细排列（历年 → 今年各季 → 本季各月 → 本月各周 → 本周每日 → 尚未归档的话题），段内按时间正序排列；父周期未闭合时由下一级补上，不留空档。
- 不再有 `memory_context_max_chars` 预算：分层记忆完整注入，不按长度截断或丢弃层级。由粗到细、段内正序的排列让最稳定的内容占住前缀缓存，新节点只追加在末尾。
- 群聊记忆与个人金字塔并列注入：群金字塔只取最近一条年总结，群画像单独成段；私聊不注入群记忆。
- 关键词召回会排除金字塔已经注入的记忆，同一内容不会重复出现。
- 画像由日总结增量更新，只使用最近 `profile_update_window_days` 天内结束的日节点；每个 scope 的历史追平后会用高层汇总回填一次。群画像只在出现新的群归档块后更新。
- 画像最多保留 `profile_max_entries` 条，注入时按重要度/更新时间取前 `profile_context_entries` 条（两者默认均为 100）。

### 觉的日程

`enable_schedule` 开启后，插件从 `${dataDir}/schedule.json` 读取日程，按当前时刻挑一条注入系统提示，告诉模型“没有具体互动时你会去做什么”。

- 文件不存在时会自动生成一份只演示写法的示例；按修改时间热加载，改完文件不用重启。
- `start` / `end` 为 `HH:MM`；省略 `end` 表示到当天结束，`end` 小于 `start` 表示跨午夜。`days` 可限定星期（`周一`…`周日`）。
- `activities` 是当前时段的候选活动，`variations` 是可选的“小插曲”，`variationChance` 控制概率。
- `vars` 是变量池，活动里用 `{变量名}` 引用；条目可以是字符串，也可以是 `{ "text": "...", "note": "..." }`，`note` 会作为补充信息一起注入。
- `dayView: true` 时注入全天视图（已经做过 / 现在 / 接下来）；`false` 只注入当前时段。
- 同一时段内所有用户拿到的文字逐字节相同（按“日期 + 条目”确定性选择），不会破坏前缀缓存；同一时段里同一个 `{变量}` 也只取同一个值。
- 只在每段对话开头几轮注入（短期记忆少于 `schedule_inject_below_entries` 条，默认 10 条）；心情为烦躁/生气时跳过；当前时刻没有条目命中时不注入。

最小示例：

```json
{
  "template": "你现在的日程安排是：{activity}。",
  "hint": "如果与用户没有具体的互动，你就会去做这件事。不要主动说明这是一份日程或系统信息。",
  "dayView": true,
  "variationChance": 0.35,
  "vars": {
    "book": ["《一本书》", { "text": "《另一本书》", "note": "一句话简介" }],
    "food": ["某道菜"]
  },
  "items": [
    { "start": "00:00", "end": "08:00", "activities": ["睡觉"] },
    { "start": "08:00", "end": "12:00", "activities": ["在看书{book}", "整理书架"], "variations": ["有人来敲门"], "variationChance": 0.5 },
    { "start": "12:00", "end": "13:00", "activities": ["吃{food}"] },
    { "start": "13:00", "end": "18:00", "activities": ["处理手头的事"] }
  ]
}
```

### 群聊省流

在群里发送 `省流`，把“你上次在本群发言到现在”的群聊用角色口吻讲成一段概要，篇幅按材料长度等比换算（一天的量约 500 字）。

- `省流 -d 3` 最近 3 天，`-m 1` 最近 1 个月，`-y 1` 最近 1 年；多个单位可叠加。不填时从你上次在本群发言算起，从没说过话则按最近 24 小时。
- 选材按“年 → 季 → 月 → 周 → 日 → 话题 → 未归档原文”由粗到细取，同一时段不会同时出现粗、细两份；未归档原文全文召回，不截断。
- 只沿用正常对话的系统提示（人格、画像、好感度、心情、常识等），不注入金字塔和关键词召回，也不写记忆、不扣使用次数；你的发言会标为「提问者」，机器人自己的发言标为「你」。
- 有 Puppeteer 时渲染成图片卡片，没有时退回纯文本。开启好感度时，好感度低于 `favorability_div_2`（默认 150）不能使用；只能在群里用。

### 群日报 / 周报 / 月报 / 年报

在群里发送 `群日报`（别名 `日报`），插件按执行时的**本地日期（零点切分）**自动选择报告类型。权限 3，只能在群里使用。

| 日期 | 报告 | 召回范围 | 最高粒度 |
| --- | --- | --- | --- |
| 1 月 1 日 | 年报 | 上一个自然年 | 月 → 周 → 日 → 话题 → 原文 |
| 每月 1 日 | 月报 | 上一个自然月 | 周 → 日 → 话题 → 原文 |
| 周一 | 周报 | 上周一 00:00 ~ 本周一 00:00 | 日 → 话题 → 原文 |
| 其余 | 日报 | 前一天 00:00 ~ 当天 00:00 | 话题 → 原文 |

优先级是 **年 > 月 > 周 > 日**：1 月 1 日即使也是周一，只出年报；1 号即使也是周一，只出月报。

#### 版面

有 Puppeteer 时渲染成一张整版报纸（刊名由 `report_masthead` 配置，默认《心眼报》）：

- **报头**：刊名、日期、期号（第 N 期）。
- **顶栏**：左侧本期热词，右侧报告覆盖的时间范围。
- **24h 活跃轨迹**：最近 24 小时每小时的群消息数柱状图，标出峰值时段。
- **数据条**：本期记忆条数 / 群友发言总条数 / 参与人数。
- **头条与导语**：8–16 字标题 + 30–60 字导语。
- **本群要闻**：可以有多条，每条 `小标题｜正文`；日报约 3 条，周/月/年报依次加长。每条是一张小卡片，偶数时一行两个；奇数时最后一条横跨两栏，变得宽而短；首条首段保留首字下沉。
- **群友金句**：日报 2–4 条、周/月报 3–5 条、年报 4–6 条，由模型在候选里按质量决定；一行两张小卡片。候选列表独立于叙述材料，覆盖整个区间的原始消息，不依赖话题摘要。
- **活跃榜**：本期发言最多的前 3 位，条数由本地统计（准确），点评由模型写。原始群消息只保留 30 天，所以年报的榜单标题是「近期活跃榜」。
- **点评**：角色口吻的编辑后记，正文右缩进，落款 `—— 昵称` 右对齐（昵称取 `nick_name_list` 第一个）。
- **报尾**：署名与生成时间。

版面直接占满图片，不留背景边。报告分两条消息发送：先发报纸图片，再发 `今日最喜欢：@某某，因为……（非常喜欢 +30好感）`。图片单独成条，不和文字混排。没有 Puppeteer 时把栏目拼回纯文本发送。

模型按 `【头条】【导语】【要闻】【金句】【活跃】【点评】【热词】` 分栏输出，渲染器逐栏排版。没有 Puppeteer 时拼回纯文本发送。

#### 最喜欢

每份报告会让角色选一个「今日最喜欢」（日报）或「本期最喜欢」（周/月/年报）的群友，并给出档位和理由：

- 档位三选一：`有点喜欢 +10`、`喜欢 +20`、`非常喜欢 +30`，由模型按自己的喜好和对方发言的质量决定，不看发言频率；默认中间档，不会每期都给最高档。
- 理由 15–40 字，必须指向材料里的具体事情，不能只写「很活跃」这类空话。
- 只能从材料里给出的群友列表中选择；同一天重复执行不会重复加分；上一份报告选过的人会从本期候选列表里排除，不能连续重复选。
- 结果跟在图片后面，和说明、图片一起组成同一条消息，并在消息里 @ 该群友：`今日最喜欢：@某某，因为……（非常喜欢 +30）`。

#### 其它

- **选材**：按对应最高粒度由粗到细取，粗层级覆盖过的时段不会再用细层级重复补；周期末尾还没形成日/周/月节点的部分，自动退回话题记忆或未归档原始消息。
- **金句候选**：每份报告都会从区间内的全部群友消息里抽一份候选列表（本地过滤 6–40 字、去重、排除图片/命令/机器人），条数按当期总消息数取对数——1500 条 → 150 条，1 万条 → 189 条，4.5 万条 → 220 条；按时间分 24 桶轮流取，保证覆盖整个区间。复读过的句子标注「复读 N 次」，发言人取第一个说这句话的人。日报/周报/月报覆盖 30 天保留期内的原文，年报的候选只覆盖最近 30 天。
- **时间范围**：日报固定取前一天 00:00 ~ 当天 00:00，周/月/年报取对应自然周期，完全按当前时钟判断，不看上次报告时间。同一天重复执行会重新生成同一段内容；`sat_meta.dailyDigestAt` 只用于同一天不重复奖励。
- **期号**：每成功发一份报告，报头期号 +1，记录在 `sat_meta.reportCount`。
- **回退**：模型没按栏目输出时，整段原文作为「本群要闻」单栏渲染；完全没有栏目标记时退回纯文本，不会因为格式漂移导致整张图发不出去。
- **群级任务**：不注入提问者的个人画像、好感度、昵称、心情等，材料也不标「提问者」，只保留人格、群画像与群常识。
- **定时建议**：日期判定按零点，所以外部定时器放在 00:00 之后即可。记忆金字塔自己的日界线仍是 04:00，周期最后几个小时如果还没有日节点，会以话题/原文形式进入报告。

#### 往期报刊

每次报告发送成功后会存档：

- 报纸图片写到 `${dataDir}/reports/g_<群号>/<YYYYMMDD>.png`。
- 数据库 `sat_report` 存相对路径和完整结构化内容（分节、统计、榜单、最喜欢），同一群同一天重复生成时覆盖。
- 永久保留，不自动清理。

在群里发送 `往期报刊 20260101`（权限 0）查看当前群的该期，只发报纸图片。图片文件丢失时会用结构化内容重新渲染；没有 Puppeteer 时退回纯文本。

### 私聊主动消息

`enable_proactive` 开启后，用户沉默一段随机时间（`proactive_min_idle_minutes` ~ `proactive_max_idle_minutes`，默认 60~120 分钟）后，机器人会基于记忆主动开口一次。

- 安静时段（`proactive_quiet_start_hour` ~ `proactive_quiet_end_hour`，默认 23:00–08:00）不发送；沉默超过 `proactive_max_idle_hours`（默认 24 小时）不再主动。
- `proactive_min_favorability` 是主动消息所需的最低好感度（默认 1000，`0` 表示不设门槛）。
- 一次沉默周期只主动一次，用户不回复就不再追发，直到他再次发言重新计时；全局每分钟最多一条。
- 主动消息只写短期记忆，不写长期记忆、不扣使用次数；状态保存在内存里，插件重载后清空（重启不会突然给所有历史用户群发）。

### 识图

消息里带的图片，以及被引用消息里的图片，都可以识别。图片只处理「已经触发对话」的消息（昵称/私聊文字）；纯图片消息仍然不触发回复，随机插话的路径也不识图。

- **配置了识图模型**（`vision_LLM_URL`、`vision_LLM`、`vision_LLM_key` 三项都填）：每条带图片的消息先调一次识图模型。提示词带上本条消息的正文，要求重点描述与问题相关的部分；结果以 `[图片内容]` 追加到用户消息里，再走正常对话流程，并随消息写入记忆。
- **没配识图模型**：把图片作为多模态内容直接附给主模型；此时固定走 `appointModel`（非思考模型不一定支持视觉）。
- **上一条纯图片**：同一个用户在当前频道的上一条消息如果是纯图片、且距今不超过 60 秒，这条消息识图时会把它一起带上；中间发过别的消息就不算。
- **识图角色匹配**：识图描述里的「特征」行加上用户正文（用户点名的角色是最强先验），会在本地角色库里按外观字段（发色/瞳色/发型/头饰/标志物/服装）+ BM25 混合打分；命中时注入 `[角色候选：名字（发色/瞳色/头饰摘要）…]`，由主模型对照图片描述判断，识图模型本身不报角色名。角色库和识别词表都在 `data/characters.json`（`vocabulary` 词表 + `characters` 角色，内置数据是东方 176 个角色）；启动时写入 `dataDir/characters.json`，之后每次启动都从该文件加载，可自行增删改词表和角色（重启生效）。旧文件名 `touhou_characters.json` 和旧格式（纯角色数组）会自动兼容/迁移。
- **引用消息**：提示词里用「（引用消息：发送者：内容）」标明被引用的消息（图片显示为「[图片]」），QQ 自带的「回复：」文本会被去掉，避免模型误读。
- **引用图片取不到时**：引用消息里有图片但下载失败（Chronocat 的引用记录可能指向本地不存在的媒体），会在提示词里注入 `[引用的图片无法识别]`（部分失败时是「引用的部分图片无法识别」），让模型明确知道看不到引用图，而不是靠猜。
- **每日限额**：`max_vision_usage` 按用户等级 0~4 配置，默认每级 30 次（`0` 表示不限制）；通行证用户不豁免。达到上限后跳过识图，文字消息照常回复。
- **安全审查**：识图结果按用户输入对待，注入前过 `censor` 审查；命中屏蔽词则整段丢弃，不注入、不写记忆，日志只记「已拦截」和长度。
- **日志**：识图成功时输出 `识图结果（userId）：<描述>`，内容是审查后的文本。
- 图片会先下载并转成 base64（QQ 图片链接常带时效或平台鉴权，外部模型自己抓容易失败）。Chronocat 的资源接口在媒体还没下载完时会返回 500，所以下载失败会自动重试 3 次（间隔 1.5 秒）；单张超过 10 MB 或重试后仍失败会跳过并记日志，下载全失败时不计入识图次数。一次最多处理 6 张。
- 识图调用失败只打日志，不影响正常回复。

## 使用示例

1. **添加常识**：
   ```
   sat.common_sense 太阳从东边升起
   ```

2. **查看某人的分层记忆**：
   ```
   sat.memory.view 123456789
   ```

3. **好感度升降效果**（`visible_favorability` 开启时）：
   ```
   [用户] sat 你今天真可爱
   [bot] @用户 谢谢夸奖~（好感↑）
   ```

4. **清空自己的短期会话**：
   ```
   sat.clear
   ```
   注意：短期记忆清空后，已经归档的长期记忆仍然保留；要一并清除请用 `sat.memory.clear`。

5. **查看群聊记忆**（在群里或任意位置）：
   ```
   sat.memory.view group      # 当前群
   sat.memory.view 123456789  # 指定群号
   ```

6. **群聊省流**（在群里）：
   ```
   省流 -d 3
   ```

7. **群日报 / 周报 / 月报 / 年报**（在群里）：
   ```
   群日报
   ```
   按本地日期自动选择：周一生成周报，每月 1 日生成月报，1 月 1 日生成年报，其余日期生成日报。外部定时器放在 00:00 之后即可。

## 注意事项

1. **成本**
   - 分层记忆在后台持续调用辅助模型；历史积压时的总调用量约为「归档次数 + 日画像 + 多子节点汇总」。
   - 辅助模型建议使用低成本模型；`summary_dry_run: true` 可先观察将要执行的任务而不实际调用。
   - 稀疏的历史日子会合并成一次调用归档，单日对话很多时才会逐日调用；遇到内容审核拒绝或连续失败的日子会自动跳过，不会卡住后续历史。
   - 画像只由最近 `profile_update_window_days` 天内结束的日节点更新，每个 scope 追平后再回填一次；不需要时可用 `profile_enabled: false` 关闭（画像需要 `profile_enabled` 与 `enable_user_portrait` 同时开启）。
   - 群聊记忆每满 100 条才归档一次，不足 100 条的块不调用模型；群画像只在有新归档块时更新。群聊原始消息 30 天后自动清理。
   - 「省流」只生成一次概要；群日报/周报/月报/年报每次只调用一次主模型（长报告会单独放宽输出上限并关闭思考模式）；主动消息每个沉默周期只生成一次；日程只读取本地 JSON，不产生 API 调用。

2. **好感度机制**
   - 启用辅助模型后，基础好感度自动增长将**失效**。
   - 每次情感分析会产生额外 API 调用；模型误判可能导致好感度异常波动，调试时建议开启 `visible_favorability`。

3. **数据安全**
   - 定期备份数据库文件（默认 `data/koishi.db`）。
   - 敏感词过滤文件路径：`data/satori_ai/output_censor.txt`。
   - 旧版记忆文件迁移前请保留备份；`sat.memory.migrate -f` 会整批替换 `legacy` 对话。
   - 不要手动修改 `sat_meta.topicStart`，归档游标被回拨会导致同一批对话重复归档。
   - 群聊记忆默认关闭；开启后只记录机器人回过话的群，群聊原始消息保留 30 天，群记忆节点与群画像长期保留。
   - `schedule.json` 可随时修改，按文件修改时间热加载，无需重启。
   - 主动消息状态只存在内存里，插件重载后清空。

4. **性能优化**
   - 推荐 `max_parallel_count` 设为 2–4（根据 API 调整）。
   - 高并发场景建议启用 `online_user_check` 防止重复请求。
   - 活跃用户/群很多时可降低 `memory_active_window_days` 或 `summary_max_scopes_per_tick`，控制后台成本。
   - 历史积压很多时反过来调大 `summary_concurrency`（同时处理的 scope 数）和 `summary_max_calls_per_tick`；单个 scope 内部始终串行，并发只发生在不同用户/群之间。
   - 群聊记忆会增加后台归档量；群很多时可保持 `enable_group_memory: false`，或通过 `memory_active_window_days` 控制参与后台处理的活跃群范围。

5. **问题排查**
   - API 原始错误看 `satori-api` 日志；归档与汇总看 `satori-summary`、`satori-heartbeat`、`satori-memory`。
   - 群聊记忆写入与活跃群恢复看 `satori-group`；主动消息看 `satori-proactive`；短期记忆 TTL 清理看 `satori-memory`；日程文件问题看 `satori-ai` 的警告。
   - `sat.memory.view [target]` 会直接输出该作用域此刻注入系统提示的完整分层记忆；群记忆用 `sat.memory.view group` 或 `sat.memory.view <群号>`，群画像用 `sat.get_user_portrait g:<群号>`。
   - `sat.clear -g` 只重置短期会话；长期记忆请用 `sat.memory.clear`。
